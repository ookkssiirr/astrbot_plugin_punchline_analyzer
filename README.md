---

## 💡 项目渊源：致敬「沈阳美食家」

本插件的设计灵感与核心幽默风格参考了开源项目 [AI 沈阳美食家](https://github.com/clean-master/ai-shen-yang-mei-shi-jia)，感谢原项目作者及贡献者。

- **冷峻解构的经典风格**：以近乎学术论文、实验报告般的客观严谨笔触，一本正经地剖析群聊中荒诞离奇、反差强烈的抽象发言与梗点。
- **标志性的三段式格式规范**：
 - **首行定调**：固定为 `笑点解析：`；
 - **逐项剖析**：条目以 `笑点1：`、`笑点2：` 展开核心反差，并以 `，很好笑。` 严格收尾；
 - **冷面总结**：末尾以 `令人忍俊不禁。[群内昵称]问的` 优雅收束（未提供昵称时回退为经典的 `令人忍俊不禁`）。
- **实事求是、坚决防捏造**：继承沈阳美食家的求真务实精神。当素材平淡无奇、缺乏明确笑点，或视频等素材解析失败时，如实反馈客观原因，坚决不编造、不凑数、不逢场作戏。

## 📖 插件简介与实际运用强化

在实际群聊运维中，往往面临高频表情包斗图、多层聊天记录合并转发、B 站等视频卡片分享、群友互相 @ 交流防误触，以及云服务器小内存防 OOM 等真实挑战。

本插件在忠实还原「沈阳美食家」经典语言风格的同时，围绕 AstrBot 生态进行了全面的**现代化工程落地与实际运用体验强化**：
1. **多模态与全场景覆盖**：从纯文本拓展至表情包 OCR 与神态理解、视频均匀采样安全抽帧（帧率/时长/体积三硬限制）、多层合并转发递归解包；
2. **群内昵称动态归属**：尾行自动识别并提取当前群聊中的**群名片**（群名片 > 账号昵称 > 用户ID），以句号隔开标注 `令人忍俊不禁。[群内昵称]问的`，极大增强群友互动的仪式感与归属感；
3. **免斜杠自然语言与开关控制**：默认支持直接发送 `笑点解析 最近30条` 或引用回复直接输入 `笑点解析`。同时在后台提供 `enable_auto_trigger` 免斜杠开关，一键收紧为仅响应 `/笑点解析` 斜杠指令，灵活适配不同水温的群聊；
4. **群友交流防误触让路**：群友之间互相 `@其他群友 笑点解析` 时智能旁路放行，绝不抢答打扰，保持群聊真实沟通的纯净；
5. **小内存轻量云服务器深度优化**：单任务锁机制、四维单调时钟隔离冷却（用户冷却 + 群组冷却），网络连接彻底断开后安全回收临时目录，保障在 1~2G 内存的小规格 ECS 上长期稳定零泄漏运行；
6. **专属定制形象**：配套经典软萌且自带冷幽默反差感的 Q 宠企鹅趴趴卡比封面（由gpt-image-2.5大师匠心生成）。

## 🚀 核心特性一览

### 1. 全场景多模态素材提取
- **引用 / 回复消息解析**：直接引用群友发言、表情包、短视频或网页分享卡片，并在正文中附带“笑点解析”或使用 `/笑点解析` 指令，插件优先深度解析被引用内容。
- **直接发送媒体触发**：在发送图片、短视频或分享卡片的同时附带关键词，自动关联当前消息中的多模态素材。
- **合并转发聊天记录递归展开**：支持群聊合并转发消息深度解包（可配置递归层级与消息条数限制），完整理解多位群友的多轮对话铺垫。
- **话题与历史溯源模式**：发送 `笑点解析 最近30条` 或 `/笑点解析 最近30条`，自动抓取群聊内存滑动窗口中的最近发言与表情包，提炼整个话题的爆笑精髓。

### 2. 双入口统一权限与灵活开关
- **免斜杠自动触发**：支持在群聊中免斜杠直接呼叫（如 直接发送 `笑点解析 最近30条` 或 `@机器人 笑点解析`）。
- **独立斜杠指令**：`/笑点解析 [最近N条]`（别名 `/笑点分析`）。
- **后台可控开关**：在插件管理面板可随时开启/关闭免斜杠自动触发。关闭后群聊中必须使用 `/笑点解析` 指令，有效防止大群闲聊刷屏，历史记录功能仍静默正常维护。
- **防误触判定**：严格识别真实 `@当前机器人` 与首部指令词，文字昵称、引用内部关键词、群友互相 @ 交流均不会产生误触。

### 3. 高并发防护与单调时钟四维冷却
- **用户冷却**：按 `(平台, 机器人, 群, 用户)` 四维严格隔离（私聊按平台/机器人/用户隔离）。
- **群组冷却**：按 `(平台, 机器人, 群)` 严格隔离，群与群之间互不干扰。
- **入口共用与截断流水线**：免斜杠入口与斜杠指令共用冷却，避免切换指令绕过限制；冷却被拦截时礼貌提示剩余等待秒数，并调用 `event.stop_event()` 截断事件流水线，避免转而触发普通 LLM 闲聊。
- **精确版本回滚**：任务预接纳记录具备 `request_id` 归属标识；在任务排队超时或取消时，仅撤销属于本请求的冷却，绝不覆盖后续并发请求建立的有效冷却。

### 4. 轻量级服务器资源硬上限保护（专为小内存服务器优化）
- **单并发保护**：单任务执行锁结合有限排队控制（`max_wait_queue`，默认 2），超额排队请求立即礼貌拒绝，杜绝瞬时并发导致服务器 OOM。
- **多媒体资源硬上限**：
 - 单视频体积硬上限：**50MB**（用户可调低 5~50MB，调高自动在运行时安全钳制为 50MB）；
 - 单视频时长硬上限：**180 秒**（用户可调低 10~180 秒，调高自动钳制为 180 秒）；
 - 单视频抽帧硬上限：**4 帧**（用户可调低 1~4 帧，调高自动钳制为 4 帧）；
 - 既不破坏生产磁盘配置文件，也能彻底防止大视频撑爆带宽与显存。
- **连接与目录零泄漏**：采用独立上下文管理与全生命周期校验（`is_fully_closed`），底层网络连接确实验证关闭后方才删除任务临时目录；抵御中途取消并支持失败安全重试。

## 💬 使用说明与交互示例

### 交互方式 1：引用解析（推荐）
1. 在群里看到任意幽默发言、表情包、短视频或分享卡片；
2. **回复 / 引用** 该消息，输入：`笑点解析` 或 `/笑点解析`。
3. 机器人将迅速定位被引用的内容，进行多模态理解并生成结构化笑点解析。

### 交互方式 2：直接发送解析
1. 发送一张表情包或搞笑短视频，并在同一条消息中发送：`笑点解析`（开启免斜杠触发时）或 `@机器人 笑点解析`；
2. 机器人将直接提取附带的图片/视频进行解析。

### 交互方式 3：话题与历史记录回溯
1. 群友们围绕某个话题热烈讨论后，直接发送：`笑点解析 最近30条`（或斜杠指令 `/笑点解析 最近30条`）；
2. 机器人将调取最近 30 条群聊发言（包含文字与图片），提炼整个对话过程中的爆笑梗点。

### 解析输出样例
```text
笑点解析：
笑点1：群友信誓旦旦声称今晚绝对不熬夜，紧接着在凌晨三点连续发送猫猫打哈欠表情包并分享游戏排位战绩，言行反差极大，很好笑。
笑点2：另一位群友精准补刀“这是今晚还是明晚”，直接戳破其自律假象，产生强烈戏剧冲突，很好笑。
令人忍俊不禁。[熬夜冠军张三]问的
```

## ⚠️ 已知兼容性与适配说明 (Known Compatibility & Adaptability)

为了确保插件在各种部署环境与消息平台中稳定运行，请在使用和运维前阅读以下已知兼容性与平台适配特性：

### 1. 消息平台与协议适配器兼容性
- **首选深度适配平台**：推荐使用 **OneBot V11 协议家族**（基于 `aiocqhttp` 适配器，如 NapCat、LLOneBot、Lagrange 等）。插件对 OneBot V11 的消息段（`Reply` 引用回复、`At` 提及、`Forward` 合并转发、`Image` 表情包、`Video` 短视频、`card` 群名片）进行了全链路深度适配与解析支持。
- **其他平台降级说明（Telegram、企业微信/微信公众平台、QQ 官方机器人等）**：
 - **消息段与富文本**：若所连接的平台或适配器未实现完整的消息段解析接口，插件将自动平滑降级至纯文本模式与用户 ID 识别模式，保障基础笑点解析可用；
 - **高级特性受限**：多层合并转发递归解包、短视频下载抽帧等特性可能因平台限制或缺少下载 URL 而不可用，插件会安全跳过或给出明确友好的文字提示，绝不导致进程崩溃；
 - **群内名片归属**：若当前平台未提供 `card`（群名片）字段，末行签名将遵循自动降级链路：`群名片 (card)` ➔ `账号昵称 (nickname)` ➔ `用户数字ID (user_id)` ➔ `经典无后缀 (令人忍俊不禁)`。

### 2. 大语言模型（LLM / Model Provider）能力要求
- **多模态视觉模型要求**：若需解析**表情包图片、群聊截图、短视频抽帧画面**，必须在 AstrBot 中为本插件配置具备视觉（Vision）能力的多模态模型（如 `Gemini 1.5 / 2.0 (Flash / Pro)`、`GPT-4o`、`Claude 3.5 Sonnet`、`Qwen-VL` 等）。
- **纯文本模型防捏造降级**：若配置的模型仅支持纯文本（如纯文本版 `DeepSeek-V3/R1` 或本地小型文本模型）：
 - **纯文字交流与群聊历史回溯**：100% 正常解析与理解；
 - **纯图片 / 表情包 / 视频请求**：由于纯文本模型缺乏视觉感知能力，插件内置沈阳美食家求真务实的防捏造机制，坚决拒绝幻觉与凭空编造，将如实反馈“未能获取图像视觉信息，现有信息不足以判断笑点”，提示用户更换多模态模型或提供文字上下文。

### 3. 系统依赖与多媒体硬限制保护
- **`ffmpeg` 宿主依赖**：短视频解析与画面均匀抽帧功能依赖运行环境（宿主机或 Docker 容器）中预装 `ffmpeg` 命令行工具。若环境缺少 `ffmpeg`，视频解析将自动安全降级为仅依据视频标题/附带文字进行分析，避免任务报错中断。
- **防止小内存服务器 OOM 的硬上限保护**：
 - **单视频体积上限**：**50 MB**（超出即刻拦截并降级提示，杜绝下载大视频撑爆网络带宽与磁盘）；
 - **单视频时长上限**：**180 秒**（超出自动跳过抽帧）；
 - **单视频抽帧上限**：**4 帧**（在视频有效时间轴内均匀采样关键帧画面，严格控制模型 Token 消耗与显存占用）。

### 4. 历史记录回溯与内存时效性
- **轻量内存环形队列**：话题回溯（如 `笑点解析 最近30条`）依赖插件在群聊内存中维护的滑动记录队列（Ring Buffer），不落盘以实现零 IO 延迟与最大隐私安全性。
- **重启时效说明**：当 AstrBot 重新启动或热重载插件时，内存队列会被清空并重新开始累计群聊消息。若群聊刚建立或机器人刚启动，实际可供提取的消息条数可能少于请求的条数，插件会自动基于当前有效抓取到的消息进行解析。

### 5. 并发保护与排队策略
- **单并发互斥锁**：为保障轻量级云服务器（如 1~2 核、1~2GB 内存实例）长期稳定运行，插件内部采取单任务互斥锁保护。
- **排队队列容量**：默认最大容纳 2 个排队等待任务（`max_wait_queue=2`），等待超时阈值为 6 秒。在群聊瞬时高并发场景下，若队列已满，后续请求会收到礼貌繁忙提示并自动安全撤销冷却，防止请求积压导致系统卡顿。

## 🛠️ 故障排查与独立运维

### 1. 常见问题
- **Q: 为什么提示“笑点解析冷却中”？** 
  A: 插件开启了用户冷却或群冷却防护，请按照提示中显示的剩余秒数稍后再试。
- **Q: 为什么视频没有抽帧画面？** 
  A: 请确保运行 AstrBot 的环境中已安装 `ffmpeg`。若视频体积超过 50MB 或时长超过 180 秒，插件将自动触发资源保护降级处理。
- **Q: 为什么提示“当前排队人数较多”？** 
  A: 为了保护服务器 CPU 与内存不被高并发拖垮，插件限制了最大排队任务数（默认 2 个），前一个任务完成后会自动接纳下一个。

### 2. 独立备份与回滚工具
插件内置了高可靠性的独立备份回滚工具脚本 [`tools/backup_and_rollback.py`](tools/backup_and_rollback.py)，可在宿主机脱离 AstrBot 独立执行：
```bash
# 查看帮助
python3 tools/backup_and_rollback.py --help

# 手动备份
python3 tools/backup_and_rollback.py backup \
  --plugin-dir /opt/astrbot/data/plugins/astrbot_plugin_punchline_analyzer \
  --config-file /opt/astrbot/data/plugins/astrbot_plugin_punchline_analyzer_config.json \
  --backup-base-dir /opt/astrbot/data/plugin_backups

# 一键回滚至指定备份点（支持全新安装与覆盖升级双场景自动化恢复）
python3 tools/backup_and_rollback.py rollback \
  --backup-id backup_YYYYMMDD_xxxxxx \
  --backup-base-dir /opt/astrbot/data/plugin_backups
```
